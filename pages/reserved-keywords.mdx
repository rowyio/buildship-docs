# Reserved Keywords in BuildShip

## Environment Variables

These are project level environment variables that can be set using the BuildShip UI (Settings > Environments).

### `LOG_LEVEL`

Number of logs generated by BuildShip can be reduced or increased by setting the `LOG_LEVEL` environment variable. `DEBUG` will generate more logs, while `INFO` will generate fewer logs.

**Valid values (case-insensitive):** `DEBUG` or `INFO`

### `DATADOG_LOG_LEVEL`

The `DATADOG_LOG_LEVEL` environment variable controls the log level for logs forwarded to Datadog. The effective value of `DATADOG_LOG_LEVEL` can not be more verbose than `LOG_LEVEL`. In other words, anything that is not logged in BuildShip can not be forwarded to Datadog. For example, if `LOG_LEVEL` is set to `INFO`, setting `DATADOG_LOG_LEVEL` to `DEBUG` will not have any effect and logs will be forwarded to Datadog with `INFO` level. If `LOG_LEVEL` is set to `DEBUG`, setting `DATADOG_LOG_LEVEL` to `INFO` will forward only `INFO` and above level logs to Datadog.

**Valid values (case-insensitive):** `DEBUG` or `INFO`

### `DATADOG_API_URL`

BuildShip can forward logs to Datadog. The `DATADOG_API_URL` is the API endpoint of Datadog without a trailing slash. For example: `https://http-intake.logs.ap1.datadoghq.com`.

The URL will have an effect only if the Datadog integration is enabled for the project. The integration is part of the enterprise plan and can be enabled by contacting BuildShip support.

## Secrets

These are secrets that can be set at the project level using the BuildShip UI (Settings > Secrets).

### `DATADOG_API_KEY`

The `DATADOG_API_KEY` secret is required for forwarding logs to Datadog. You can find the API key in your Datadog account settings.
